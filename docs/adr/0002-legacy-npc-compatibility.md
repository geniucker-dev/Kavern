# ADR 0002: Legacy npc Compatibility

## Status

Accepted for MVP Spec v1; amended by ADR 0005 for source-informed protocol compatibility.

## Context

Some deployments may need to connect existing stock `npc` clients from `https://github.com/yisier/nps`. Kavern will support only the smallest legacy mode needed for server-side configured tunnels.

## Decision

Kavern will provide a legacy gateway package:

```text
internal/gateway/legacy_npc
```

The only supported invocation is:

```sh
npc -server=<host:port> -vkey=<vkey>
```

Legacy tunnel behavior is configured server-side in `kavernd`. Legacy clients must not define arbitrary targets.

The pinned v0.26.34 protocol contract is source-informed and independently implemented as described by ADR 0005. This is not a clean-room compatibility claim.

## Credential Handling

- `vkey` belongs to `Device`, not `User`.
- `vkey` is generated by Kavern by default, not chosen by users.
- `vkey` generation must use at least 32 bytes of cryptographic randomness.
- `vkey` should be encoded with base64url or an equivalent safe encoding.
- `vkey` is shown only once at creation or rotation.
- Never store raw `vkey`.
- Lost `vkey` values cannot be recovered and must be rotated.
- Rotating a `vkey` invalidates the old legacy lookup key.
- Stock `npc` sends a legacy wire token expected to be `md5(vkey)` hex.
- Legacy wire token handling is only a legacy bearer-token compatibility boundary.
- `LegacyNpcGateway` receives the wire token, validates its format, computes `HMAC-SHA256(server_secret, wire_token)`, and looks up `DeviceCredential`.
- Never log or persist the raw wire token.
- Never store raw `md5(vkey)`.
- The raw `vkey` is not needed during connection authentication.
- Keep MD5 isolated to the legacy compatibility boundary or narrowly scoped helper.
- `kavern-agent` must not use MD5.
- Disabled devices must not authenticate through legacy `npc`.

## Test Requirements

Real stock `npc` compatibility must not be considered complete unless an integration test actually executes a real `npc` binary from `yisier/nps`.

Legacy npc integration tests must:

- Live under `tests/legacy_npc`.
- Use a build tag such as `legacy_npc_integration`.
- Use `NPC_BIN=<path-to-npc>`.
- Require `NPC_BIN` when the build tag is enabled.
- Fail clearly when the build tag is enabled and `NPC_BIN` is missing.
- Avoid silent skips for missing `NPC_BIN`.
- Stay out of normal `go test ./...`.

Fake clients, mocked handshakes, or protocol simulations are not sufficient for acceptance.

## Binary Acquisition

The repository may later provide:

- `scripts/build-npc.sh`
- `scripts/fetch-npc.sh`

These scripts may fetch or build stock `npc` from a pinned `yisier/nps` tag. They must not vendor `yisier/nps` source into this repository. The pinned tag or version must be documented in `docs/TESTING.md`.

Before Gate 5 starts, the pinned `yisier/nps` tag or version must be selected and documented. These scripts must not use `master` or `latest`. They may clone or download into temporary, cache, or testbin locations, but must not vendor `yisier/nps` source into the Kavern repository.

## Out of Scope

- `npc -config`.
- `conf`.
- `file`.
- `p2p`.
- `secret`.
- `register`.
- nps Web UI.
- nps API.
- Copying, importing, vendoring, or reusing `yisier/nps` GPL code, source files, identifiers, comments, tests, queue implementations, or window implementations.

## Consequences

- Legacy compatibility is intentionally narrow.
- The gateway may contain protocol-specific logic, but business logic must not.
- Compatibility cannot be accepted until real binary integration passes.
- Separate license/compliance review is required before closed-source commercial distribution.
