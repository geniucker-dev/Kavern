# ADR 0001: Project Scope

## Status

Accepted for MVP Spec v1.

## Context

Kavern is being created as a brand-new tunneling project in the `kavern` repository. It may partially support stock `npc` from `https://github.com/yisier/nps` as a legacy client, but the project must not become an `nps` rewrite, fork, or compatibility clone.

## Decision

Kavern will define native domain, session, routing, and data-plane abstractions.

Project names are fixed:

- Product: Kavern
- Server binary: `kavernd`
- First-party agent binary: `kavern-agent`
- CLI binary: `kavernctl`
- New protocol: Kavern Agent Protocol v1, KAPv1
- Future mux: `kavernmux`

The supported legacy `npc` invocation is limited to:

```sh
npc -server=<host:port> -vkey=<vkey>
```

All other `nps` and `npc` features are out of scope unless explicitly approved by a later ADR.

## Consequences

- Kavern business logic will not import legacy protocol packages.
- Kavern will not copy, import, vendor, or derive implementation from `yisier/nps` GPL source.
- Compatibility with stock `npc` is a narrow gateway boundary, not a product identity.
- `AGENTS.md` is the canonical project instruction file generated by this spec process.
- The canonical MVP package layout is defined in `docs/SPEC.md`; later layout changes require an ADR.
- Gate 0 does not approve implementation. Generated files, diffs, and test output must be reviewed before any code is written.

## Explicit Non-Goals

- `nps` rewrite.
- `nps` fork.
- `npc -config`.
- `conf`.
- `file`.
- `p2p`.
- `secret`.
- `register`.
- nps Web UI.
- nps API.
- Fake compatibility claims.

## Review Requirement

After Gate 0 files are generated, they must be reviewed before any implementation code is written.
