# Local MVP operation

> Historical local-assembly baseline. The bootstrap `limits`/agent target-map and no-WebUI descriptions below were superseded by reviewed server-owned configuration, online management, renewable lifecycle and WebUI work. For runnable current native operation, use [the root quick start](../README.md) and [current WebUI contracts](LOCAL_WEBUI.md). Historical evidence remains unchanged.

The local assembly passed independent r2 review as 2b814ec; Gate 7 passed as bc11abc. Gate 8 and final local MVP acceptance passed independent review on 2026-10-09. It does not authorize deployment, public exposure, or production credential creation. The supported execution platform for the local state lock is Linux; other platforms fail closed when opening state. Ordinary tests use isolated temporary state, certificates and credentials and require neither internet nor NPC_BIN.

## Build and inspect

```sh
go build -o ./bin/kavernd ./cmd/kavernd
go build -o ./bin/kavern-agent ./cmd/kavern-agent
go build -o ./bin/kavernctl ./cmd/kavernctl
./bin/kavernctl help
./bin/kavernd -h
./bin/kavern-agent -h
```

The operator supplies existing TLS certificate/key files, a CA trust file, and external environment secrets. `KAVERN_MASTER_KEY` must contain exactly 32 random bytes encoded as unpadded base64url. The master key is never stored in the state file. If legacy connections are enabled, `KAVERN_SERVER_SECRET` must contain at least 32 random bytes in the same encoding and must remain stable across restarts. These values are not generated by daemon startup.

## Offline administration

Use a private directory for state. The CLI refuses an existing state file with group/other permissions, symlinks, duplicate IDs/listeners, unknown references, and invalid addresses. Stop the daemon before mutations; the daemon and CLI hold the same exclusive lock. Changes take effect after restart.

```sh
./bin/kavernctl init-state -state ./private/state.json -user owner -project local
./bin/kavernctl add-device -state ./private/state.json -id workstation -project local -kind kapv1
./bin/kavernctl add-tunnel -state ./private/state.json -id echo -device workstation -listen 127.0.0.1:9000 -target 127.0.0.1:9001
./bin/kavernctl rotate-device -state ./private/state.json -id workstation -kind kapv1
./bin/kavernctl set-device-enabled -state ./private/state.json -id workstation -enabled=false
./bin/kavernctl set-tunnel-enabled -state ./private/state.json -id echo -enabled=false
```

Device creation/rotation emits the newly generated credential once on stdout, after state has been saved. Keep that output private; it is not a log. Lost native secrets or legacy vkeys must be rotated. Native device secrets are persisted using AES-256-GCM with a fresh nonce and device-bound associated data. Legacy state contains only the HMAC lookup key, never a vkey or MD5 wire token. State updates use a private temporary file, file fsync, rename and directory fsync.

For a legacy device use `-kind legacy` with the external server secret available. The CLI offers offline setup only; there is no management HTTP API or Web UI.

## Server configuration

```json
{
  "control_listen": "127.0.0.1:8024",
  "cert_file": "./certs/server.pem",
  "key_file": "./certs/server-key.pem",
  "state_file": "./private/state.json",
  "master_key_env": "KAVERN_MASTER_KEY",
  "limits": {"max_streams": 64, "max_inflight": 1048576, "max_buffer": 8388608}
}
```

For stock pinned npc add `legacy_listen` and `server_secret_env`. Legacy and native handlers are separate. Native TLS verifies certificates; there is no insecure command-line option. Listen addresses are explicit, with native control defaulting to loopback when omitted. Non-loopback listeners require an explicit configured address. The public TCP listeners come from stored enabled tunnels on enabled devices.

```sh
./bin/kavernctl validate -kind server -config ./server.json
./bin/kavernd -config ./server.json
```

The daemon prints one `server_ready` JSON record containing actual listener addresses and a tunnel-to-public-address map. Port zero is useful for isolated tests. It prints no credentials.

## Agent configuration

Put the one-time native secret in the external environment variable named by `secret_env`. The agent resolves tunnel IDs using its own target map; caller addresses and server tunnel target metadata cannot select an arbitrary native target.

```json
{
  "server": "127.0.0.1:8024",
  "device_id": "workstation",
  "secret_env": "KAVERN_DEVICE_SECRET",
  "ca_file": "./certs/ca.pem",
  "targets": {"echo": "127.0.0.1:9001"},
  "carriers": 2,
  "limits": {"max_streams": 64, "max_inflight": 1048576, "max_buffer": 8388608}
}
```

```sh
./bin/kavernctl validate -kind agent -config ./agent.json
./bin/kavern-agent -config ./agent.json
```

`agent_ready` is emitted after the server confirms that all requested carriers are attached. There are at most four carriers per authenticated session. The agent reconnects the entire session after control/carrier failure with backoff from 100 ms to five seconds; existing application streams are not replayed. SIGINT/SIGTERM closes listeners/connections and joins owned loops/handlers. State and configured certificates are retained.

## Resource and timeout contract

- Defaults: 64 streams per carrier, 1 MiB pending local write payload, 8 MiB combined payload budget, two agent carriers, four maximum carriers. Streams and accepted handlers are both bounded. Excess streams/carriers fail clearly; excess writes wait with context cancellation. Canceling an in-progress backend write retires that carrier and joins the write; this can end other streams on the same carrier. The agent then reconnects the control session and does not replay application bytes.
- `max_inflight` means owned pending synchronous write payload until the backend write returns. It is not an acknowledgement window. Writes copy at most 16 KiB per chunk, and all streams share the carrier budget.
- `max_buffer` includes backend queued receive payload plus owned pending write copies. The backend reserves 65,535 bytes of headroom because its wire frame length is 16-bit; a hostile peer is not assumed to honor our configured outbound frame size. Object/TLS/socket/kernel overhead is excluded; this is not a total process RSS promise.
- Native control frames are length-prefixed JSON of at most 4,096 bytes. Duplicate keys, unknown fields, invalid UTF-8, trailing JSON, and nesting beyond 32 levels fail closed. Configuration/state JSON is capped at 1 MiB.
- Native handshake and target dialing: five seconds. Metadata header: five seconds. Control heartbeat: ten seconds; idle: 30 seconds; session lifetime: one hour. Native auth challenges: two minutes. Public TCP routes have a five-minute absolute deadline, not a reset-on-progress idle timeout. A per-route deadline context covers stream opening and both copy directions; expiration closes the inbound connection, retires the route, releases its stream lease, joins cancellation cleanup and frees its handler slot even when the remote response remains silent.
- Session observability keeps at most 1,024 recent records across all devices, evicting oldest records. ListForDevice may omit an old still-current session; routing uses the current index and never depends on history. This is not a persistent audit log.
- The standalone legacy Gateway.Serve entry point also caps accepted handlers at 256, closes overload connections, and cancels/closes/joins accepted handlers on exit. kavernd already uses a shared 256-slot budget across all listener types.
- Auth challenges, active registry entries, and used carrier nonces are capped at 4,096 each. Expired challenges are pruned on insertion; sessions reject expired binds/opens and the control owner retires them at expiry. A daemon accepts at most 256 concurrent transport/public connections in total.

## Current accepted local MVP

`go test -race ./cmd/kavernd -run TestActualCommandsNativeTLSHalfCloseAndRestart -count=1` builds and runs all three actual commands with race instrumentation. It exercises offline setup, verified TLS, two attached carriers, a 262 KiB response generated only after request EOF, exclusive state locking, daemon/agent restart from persisted encrypted state, and graceful process shutdown. All resources are temporary and loopback-only.

The native mux adapter uses bounded stream records with explicit directional EOF (ADR 0006). This avoids premature buffered-data reclamation during backend bidirectional FIN handling. It is a native Kavern transport detail and does not change legacy npc framing.

Gate 7 loopback measurement is independently reviewed. See SECURITY.md for Gate 8 evidence boundaries and ACCEPTANCE.md for the final acceptance map. This document does not claim WAN performance, high availability, arbitrary npc versions/platforms, hot credential changes, or production readiness.
